# Тетрадь

Веб-приложение для русских рукописных конспектов: фотографии → проверяемые блоки текста,
LaTeX и рисунки → подтверждённые страницы → общий DOCX. Работает на Windows и в браузере
телефона. Интерфейс, вопросы и сообщения об ошибках — на русском языке.

## Запуск в подготовленной облачной среде

```bash
cd /workspace/-
./run.sh
```

В обычном браузере на машине с сервером откройте адрес `http://127.0.0.1:8000`.
Сервис остаётся запущенным, пока работает процесс. Данные сохраняются отдельно от процесса.
Проверка сервера: `GET /api/health` возвращает `{"ok":true,...}`.

## Windows 10/11

Установите 64-битный Python 3.12 с официального python.org. В PowerShell в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.windows.lock
.\.venv\Scripts\python.exe run.py
```

Для первой установки также доступен `install-windows.bat`: он проверяет каждый шаг и останавливается при ошибке.
После установки можно запускать `start-windows.bat`. Python 3.12 и x64 обязательны для
этого lock-файла. Транзитивные версии и хеши Windows разрешены отдельно; работа на
настоящей Windows-машине в облаке не проверялась.

Для телефона в той же Wi-Fi-сети задайте пароль и разрешите серверу слушать сеть:

```powershell
$env:APP_PASSWORD="ваш-длинный-пароль"
.\.venv\Scripts\python.exe run.py --host 0.0.0.0
```

На телефоне откройте адрес компьютера в локальной сети с портом 8000. Windows может
запросить разрешение брандмауэра для частной сети. Для удалённого доступа используйте
HTTPS-прокси с паролем приложения; встроенная схема предназначена для одного владельца,
без ролей и разделения данных между пользователями.

## Linux: установка с нуля

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.lock
./run.sh
```

Для облака доступен `uv pip sync --python /workspace/handwriting-venv/bin/python
--require-hashes --strict requirements-dev.lock`.
Распознавание выполняет настроенный API-провайдер. PyTorch, Transformers, GPU,
отдельный сервер базы данных и Node.js для приложения не требуются. KaTeX и шрифты
включены в репозиторий: формулы отображаются без обращения к CDN.

## Первый конспект

1. Создайте проект и укажите предмет. Загрузите несколько JPG, PNG, HEIC или PDF.
   PDF разворачивается в отдельные страницы, а исходный файл сохраняется. Возможные
   дубликаты предлагается сравнить: приложение не удаляет их автоматически.
2. Для автоматического распознавания откройте **Настройки**, укажите HTTPS-адрес
   OpenAI-совместимого API, модель с анализом изображений и ключ. По умолчанию:
   `https://api.openai.com/v1`, `gpt-4.1`. Нужны поддержка Chat Completions, изображений
   и `response_format: json_object`. Подтвердите отправку изображений провайдеру.
3. Нажмите **Распознать** для страницы или **Все страницы** для очереди. Запросы
   могут тарифицироваться провайдером. Загрузка файлов сама по себе не вызывает API.
   Статус и ошибки видны на странице; после ошибки можно повторить обработку.
4. Выберите сомнение: его область выделится на фото. Ответьте вариантом, свободным
   текстом или отредактируйте блок. Поддерживаются «Тем — это температура»,
   «На вертикальной оси Y меняем на X», «Остальное правильно», «Всё верно».
   При неоднозначном адресате приложение просит выбрать конкретный блок/вопрос.
   Для замены подписи рисунка нужна доступная структурированная схема; иначе
   используйте редактор схемы. Оригинальное изображение приложение не подделывает.
5. **Всё верно** подтверждает только текущую страницу. Открытые вопросы на других
   страницах остаются открытыми. Кнопка **Подтвердить страницу** требует ответить
   на все её вопросы. Любая последующая правка снова делает страницу черновиком.
6. **Экспорт в Word** создаёт весь документ заново, без накопительного дописывания
   тех же страниц. По умолчанию включены только подтверждённые страницы. Можно
   отдельно включить помеченные черновики и пояснения приложения к рисункам.

Без ключа доступны все действия с файлами, ручные блоки и вопросы, LaTeX, рисунки,
история, профиль почерка, подтверждение, DOCX и резервные копии. Вместо результата
распознавания приложение показывает требование настроить провайдера, а не фиктивный текст.

## Редактирование и рисунки

На широком экране рядом расположены фото с масштабированием, конспект и вопросы.
На телефоне переключайтесь вкладками. Есть светлая и тёмная темы.

В **Редактировать → Выделить на фотографии** можно задать область блока пальцем или
мышью. Кнопки ↑ ↓ переставляют страницы, не меняя их исходные номера. Исходный номер
редактируется отдельно над рабочей областью.

Формулы хранятся в LaTeX и отображаются KaTeX. В Word они преобразуются в редактируемые
OMML: дроби с горизонтальной чертой, векторные акценты, индексы, пределы, интегралы.
Если неподдерживаемая формула не преобразовалась, DOCX сохраняет её LaTeX, а интерфейс
сообщает число таких формул. Семь формул из задания проверены без такого отката.
Microsoft Word в этой Linux-среде не запускался; структура DOCX, OMML и размеры рисунков
проверены программно.

Рисунок по умолчанию — фрагмент оригинала. Отдельно показывается пояснение модели.
Редактор перерисовки предлагает безопасные SVG-примитивы (линии, стрелки, точки, подписи,
штриховые линии, залитые многоугольники) и пять заготовок типовых схем. Координаты
в редакторе задаются в области 1000×700. Заготовка не выдаётся за распознанный рисунок.
Перерисовку необходимо просмотреть и явно подтвердить. В DOCX она вставляется как PNG,
в резервной копии остаётся структурированная геометрия. Дробные и числовые значения
по схематическому изображению не вычисляются автоматически.

## Профиль почерка

В профиль один раз добавляются четыре текстовые заметки из вашей общей переписки.
Их можно менять и удалять; фотографии и старые документы не импортировались.
Подробности: [учтённый контекст](docs/CONTEXT.md).


**Мой почерк** позволяет загрузить фото алфавита, цифр, символов или быстрого письма и
указать правильную запись. Образцы можно просматривать, редактировать, удалять и
экспортировать и импортировать без повторного добавления одинаковых пар. Особенности и обозначения разделены на общие и относящиеся к предмету.
При подтверждении страницы можно сохранять блоки с заданными областями автоматически.
Фрагменты с `[?]` не добавляются как достоверные образцы.

Персонализация — подбор до шести последних подходящих подтверждённых изображений
(общие и по предмету) и заметок в контекст запроса. **Дообучение модели не выполняется.**
Модель не заменяет личную проверку фамилий, чисел, неоднозначных букв и физических утверждений.

## Хранение, история и восстановление

По умолчанию всё хранится в `.data/` рядом с проектом:

- `notebook.sqlite3` — проекты, порядок, документы, версии, вопросы, исправления, очередь,
  результаты распознавания, профиль и настройки;
- `assets/` — оригиналы, нормализованные страницы и подтверждённые фрагменты;
- `server.key` — ключ шифрования сохранённого API-ключа (права 600 в Linux).

Каталог можно изменить через `--data-dir` или `NOTEBOOK_DATA`. Сохраняйте и базу, и файлы.
Распознанный результат не перезаписывает старые версии. **История / отмена** позволяет
просмотреть и восстановить версию как новый черновик. Удаление страницы/проекта требует
подтверждения и не является действием отмены; сначала сделайте резервную копию.

**Резервная копия** выгружает проект, оригиналы, структурированные документы, формулы,
геометрию, историю исправлений, результаты распознавания и относящийся к проекту профиль
в ZIP. **Восстановить** создаёт отдельную копию проекта, сохраняя существующие данные.
Ключи API и настройки доступа в ZIP не включаются. Для полного переноса сервера
нужен также защищённый перенос `.data/server.key` либо повторный ввод API-ключа.

Существующий DOCX импортируется в диалоге экспорта: его исходное содержимое сохраняется
перед новыми страницами. Не импортируйте обратно экспорт того же проекта, если не хотите
повторить уже имеющийся в нём материал.

Запрос, прерванный перезапуском сервера, помечается ошибкой и не повторяется автоматически:
пользователь сам решает, делать ли новый платный запрос. Остальная явно запущенная очередь
сохраняется. Запускайте один процесс Uvicorn (стандартный запуск уже использует `workers=1`).

## Секреты и сеть

Ключ можно задать через серверную переменную `OCR_API_KEY` (приоритетнее настройки),
а адрес/модель — `OCR_BASE_URL` / `OCR_MODEL`. В интерфейсе ключ отправляется серверу
один раз, шифруется и никогда не возвращается клиенту. Запросы с ключом не журналируются.
Сохранение настроек не проверяет баланс или качество модели; проверяется настоящий
запрос распознавания выбранной страницы.

Если распознавание завершилось отказом, сообщение различает HTTP 401 (авторизация),
403 (доступ), 429 (лимиты) и известные коды провайдера. Например, `invalid_api_key`
указывает на непринятый ключ, `unsupported_country_region_territory` — на недоступность
сервиса в регионе, а `insufficient_quota` — на квоту или оплату API. Неизвестный ответ
провайдера не показывается целиком: он может содержать ключ или личные данные.
Ключ должен принадлежать тому же сервису, который указан в адресе API. Ключ OpenAI
создаётся в кабинете platform.openai.com; пароль аккаунта и ключ другого сервиса для
api.openai.com не подходят. Секреты отправляйте только через настройки приложения,
а при диагностике сообщайте адрес, модель, HTTP-статус и безопасный код ошибки.

Для стандартного провайдера нужен HTTPS-доступ к `api.openai.com`. Другому провайдеру
нужно разрешить его конкретный домен в сетевых настройках среды. Закрытые/локальные
адреса провайдеров и небезопасный HTTP не допускаются. Для ручной работы сеть не нужна.

## Проверки

Инструменты разработки устанавливаются отдельно от приложения:

```bash
uv pip sync --python /workspace/handwriting-venv/bin/python --require-hashes requirements-dev.lock
```

```bash
/workspace/handwriting-venv/bin/python -m pytest -q
PLAYWRIGHT_BROWSERS_PATH=/workspace/.cache/ms-playwright /workspace/handwriting-venv/bin/python tests/browser_smoke.py
```

Для браузерного теста предварительно установите Chromium командой `python -m playwright
install chromium`. Сетевые домены установщика: `cdn.playwright.dev` и
`playwright.download.prss.microsoft.com`. Браузер не нужен для обычного запуска приложения.

Автотесты используют созданные программно изображения и явно подменённый тестовый
провайдер. Это не результаты настоящего OCR. Браузерный тест проходит ручной сценарий
через реальный интерфейс и сохраняет скриншоты и контрольный DOCX в `artifacts/`.
Проверка перезапуска и сохранности данных выполняется в тестах API.

Фотографий владельца и API-ключа при разработке не было. Качество на вашем почерке,
реальный платный запрос и работа в установленном Microsoft Word не проверены.

## Устройство проекта

- `notebook/app.py` — FastAPI, очередь, API, вход и управление страницами;
- `store.py` — SQLite, файлы и версии;
- `provider.py` — заменяемый модуль распознавания и безопасные настройки;
- `corrections.py` — исправления с проверкой области действия;
- `models.py` — проверка структурированного документа;
- `math_export.py`, `exporting.py` — OMML, DOCX, резервные копии;
- `diagrams.py` — безопасный SVG и растровый экспорт геометрии;
- `static/` — русский адаптивный интерфейс без сборки и внешних CDN.
